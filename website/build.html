Read the chain over HTTP

        
The public API answers plain GET requests with JSON. Pick a request and read the answer.

      

      

        

          API console
          
        

        

          

          

            

              
              

                
                
              

            

            

            

          

        

      

      

        
Read-only and open
No key and no account. Cross-origin requests are allowed, so a web page can call the API directly.

        
Your own node answers too
Every full node serves the same read routes on port 8645. Point your code at http://127.0.0.1:8645 and you depend on nobody's server.

        
Amounts are whole numbers
Amounts come in units: 1 YSR is 100,000,000 units. Read them as integers or strings and never as floating-point numbers.

      

    

  


    

    

      

        
Run a full node

        
A full node keeps its own copy of the chain and checks every block itself. It takes nothing on trust, not from other nodes and not from this website.

        What a node checks in every block
      

      

        
# Get the source and build the node
git clone https://github.com/dabitlex/YSKAR.git
cd YSKAR/node
npm install
npm run build

# Start it: connect to the seed nodes, download the chain, check every block
node dist/yskar-node.cjs mine --data ./knoten \
  --seed pool.yskar.app:8646 --seed yskar-seed2.dynv6.net:8646 \
  --no-upstream

          

        

          
You need
Node.js 22.13 or newer and Git. The node stores the chain with the SQLite module built into Node.js.

          
Ports
TCP 8646 for other nodes, 8645 for the HTTP interface that miners and wallets use.

          
Clock
Keep the system clock correct. A block dated more than 120 seconds ahead of your node's clock is rejected.

          
Seed nodes
The command-line node has no seed built in. Name both seed nodes, as in the command above.

          
--no-upstream
Belongs in the command. Without it the node would also exchange blocks with the project's database mirror, which only accepts blocks from the main node.

        

        
# Mine against your own node, in a second terminal
cd YSKAR/miner
node src/cli.mjs --address ysr1... --api http://127.0.0.1:8645

          

        
On Windows, type npm.cmd in place of npm in PowerShell. If you prefer a window to a terminal, Node Core runs the same full node on Windows and Linux.

What is where

        
One repository holds the consensus code, the node, the miner and the tests that guard them.

      

      

        

          
src/lib/core/
Consensus: header, difficulty, transactions, state, wallet derivation

          
src/lib/node/fullnode/
Full node: chain, mempool, mining interface, read API, command line

          
src/lib/node/p2p/
The node-to-node protocol

          
src/lib/pool/
PPLNS accounting and the split of the block reward

          
node/
Build of the command-line full node

          
node-core/
Node Core for Windows and Linux, with the GPU miners

          
miner/
The command-line miner, without dependencies

          
observer/
The observer: a small read-only tool that downloads the chain and recomputes every block

          
tests/
Tests of consensus, node, P2P, pool and wallet

          
docs/
The documentation listed above

Signed messages

        
A wallet can prove that it controls an address without moving a coin. All YSKAR software signs and checks the same text format.

      

      

        
YSKAR Signed Message
purpose: login
domain: lab.yskar.app
address: ysr1…
nonce: <32 hex>
issued: <2026-11-11T12:00:00Z>
expires: <2026-11-11T12:10:00Z>

        
    
          
  • The signature is Ed25519 over the raw UTF-8 bytes of the whole message, checked by the same rule as on the chain.
    • 
          
  • The first line makes it safe: a transaction is binary and never starts with these words, so a signed message can never count as a transfer.
    • 
          
  • YSKAR Wallet and Node Core sign such messages. YSKAR Lab uses them to sign you in without a password.
    • 
        

      

    

  


    

    

      

        
Contribute and report

      

      

        
Changes to the code
CONTRIBUTING.md says which checks must pass before a push: the type checks and the full test suite.

        
Ideas and proposals
Proposals for the protocol and the software are discussed in the open at YSKAR Lab. You sign in with your wallet.

        
Security problems
Report them as an issue at github.com/dabitlex/YSKAR/issues. Issues are public: describe what you saw and how to reproduce it, and never post your 12 words, a PIN, a wallet file or a key.
