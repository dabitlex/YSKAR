# Checking the native miner on a desktop machine

This note is for developers who change the native miner of the Android app. It shows how to
check the miner core with an ordinary JDK, without an Android device.

The core of native mining (`Sha256d`, `Sha256dKern`, `Rechenweg`, `MiniJson`, `NativMiner`) has
no Android dependency. It can therefore be compiled and run here against a real YSKAR node: the
same `MiningServer` class the full node uses, started locally on the regtest network by
`knoten.ts`.

```bash
# 1. Hash: genesis block, 2000 random headers against MessageDigest, all computation paths
mkdir -p /tmp/jb
javac -d /tmp/jb android/app/src/main/java/net/yskar/wallet/{Sha256d,Sha256dKern,Rechenweg,MiniJson,NativMiner}.java \
      android/pruefung/ShaPruefung.java android/pruefung/MinerPruefung.java
java -cp /tmp/jb net.yskar.wallet.ShaPruefung

# 2. Against a local node: shares, blocks, dropped session,
#    power control, stop, pool mode on a node without a pool, wrong address
node --experimental-strip-types android/pruefung/knoten.ts 18655 &
java -cp /tmp/jb net.yskar.wallet.MinerPruefung http://127.0.0.1:18655 ysr1qqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqregwfw
```

Run the commands from the repository root.

| File | Purpose |
|---|---|
| `ShaPruefung.java` | Checks the hash code against the genesis block, against `MessageDigest` and across all computation paths (`Rechenweg`) |
| `MinerPruefung.java` | Runs `NativMiner` against the local node |
| `knoten.ts` | Local test node: `MiningServer` on regtest, chain in memory; the argument is the port |
| `gen_sha.py` | Generates `Sha256dKern.java` |

`Sha256dKern.java` is generated by `gen_sha.py`. Do not edit it by hand:

```bash
python3 android/pruefung/gen_sha.py > android/app/src/main/java/net/yskar/wallet/Sha256dKern.java
```

How the miner works inside the app is described in [docs/APP.md](../../docs/APP.md).
